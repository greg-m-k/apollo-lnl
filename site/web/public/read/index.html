One question, three services

A reception screen asks one question: who is this person, what is their job, and what badge do they carry? Three domain services own those three answers: HR, Employment and Security, each with its own database. Federated services ask all three at the moment of the request: a router works out a query plan, calls each service and combines the replies. Event-driven projections ask one query service, which reads a combined copy that was built earlier from the three services' events. Run both and compare where the time goes. New to these terms? The first run is usually the slowest: on the live site often over a second, against about
    150ms after that. Each service is a Cloudflare Worker, and a Worker that has not served anyone for a while starts afresh. It loads
    its code, the router reads the supergraph and works out the query plan, and each database opens its connection. Later runs reuse
    all of that. A federated read goes through four Workers (the router, HR, Employment and Security), so it has four chances to meet
    one that is starting; a projection read goes through one. The console numbers the requests each copy has served, and request #1
    is a fresh start. In the apollo-demo the services run all the time, so you see this only after a deploy or a restart.


  
Federation's total is roughly router + HR + the slower of Employment and Security:
    the two run side by side, but both wait for HR, because they need the Person it returns. The projection's total is one database read,
    whatever the three teams' services are doing.
